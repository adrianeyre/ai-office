# Agents follow only Guidelines the Owner approved

The Owner wants to give a Floor's repository its own Guidelines ("in this repository, migrations are written this way") that every Agent follows, scoped to the files they apply to. The natural home for them is the repository: they are versioned with the code they describe, reviewed in a pull request, edited in any editor, read by the people who work on it, and written by a Grilling Session's pull request like the PRD and ADRs. But anyone who can push to the repository could then plant instructions that every later Agent follows as the Owner's, which is why Agents ignore `CLAUDE.md`, `AGENTS.md` and `.agents/` in their clone today (pen-test finding P1-9). So **Guidelines are repository files, `.agents/guidelines/*.md` on the Floor's default branch, and Agents get each one only in a version the Owner approved**. AI Office reads the folder through the GitHub App, never from a clone. A version is approved when the last commit that changed it reached the default branch through a pull request the Owner merged, or was pushed by the Owner; or when the Owner approves it in the Floor admin. Any other version is **awaiting approval**: Agents keep the last approved version (or nothing, for a new file) until the Owner approves it or dismisses it.

## Considered Options

- **Read the files as they are**, from the default branch: the simplest, and what a coding assistant does with its own instruction files. But it reopens P1-9, and worse: a Guideline is followed as a rule, not read as data, so one push by a collaborator, a leaked token or a merged pull request that slipped a line in would reach every later task of every Agent on the Floor with nobody in the way.
- **Keep them in AI Office's database only**, edited in the Floor admin like Office-wide memory: safe by construction, but they would live apart from the code they describe, with no history or review beside it, out of sight of anyone working on the repository, and out of reach of a Grilling Session's pull request, so `/guidelines` could not write them where the Owner reviews everything else.
- **Repository files, given to Agents only as the Owner approved them** (chosen): the files keep the repository's history, review and tools, and the database keeps only what the Owner approved, so nothing anyone else pushes reaches an Agent until the Owner says so.

## Consequences

- **Who merged or pushed is GitHub's record, never a commit's author.** AI Office authors every commit as the Owner (ADR 0002), and anyone can write any name in a commit, so author and committer prove nothing. A pull request counts when GitHub says the Owner merged it: the Owner's GitHub login from General Settings' **Intake** card, as for intake and `ai-office:auto-merge`, or the Owner's **Approve and merge** in AI Office. An automatic merge by the Merge Policy never approves a Guideline.
- **Approved versions are kept in the database with their content hash**, so a later read of the same content needs no new approval, and a file put back to an approved version is approved again. A version approved in the Floor admin is approved for exactly the content the Owner saw.
- **A version awaiting approval is shown, not used.** The Floor admin shows its difference from the approved one with **Approve** and **Dismiss**, and the Owner gets one action Notice per Floor, "Guidelines changed on web-shop: 2 awaiting approval". On a repository many people push to, every change someone else makes waits for the Owner: that is the cost of the decision.
- **A file deleted on the default branch, by anyone, stops reaching Agents at once.** A deletion gives Agents nothing new to follow, so it needs no approval; the Floor admin and the Activity Feed show it, and the Owner can put the file back.
- **The clone stays hidden.** P1-9's rule is unchanged: the agent tools still ignore `.agents/` in the clone, and Agents see Guidelines only as AI Office gives them, as read-only files beside the memory mount in sandboxes and quoted between markers for reviewers and the Manager.
- **Agents cannot approve their own.** An Agent's pull request that changes anything under `.agents/guidelines/` (or `.agents/specs/`) goes to the Owner whatever the Floor's Merge Policy, as repository memory does (P1-3). An Agent may propose a change, which waits for the Owner, and no model accepts one, as no model accepts Role memory (ADR 0005).
- **A Guideline never carries a credential.** A version with a line that looks like one is not approved, and the Floor admin names the line, never what it holds.
- AI Office reads the folder through the GitHub App at intake and before each task, so each task gets the Guidelines as they stood when it started. A Floor without `.agents/guidelines/` behaves exactly as before.
