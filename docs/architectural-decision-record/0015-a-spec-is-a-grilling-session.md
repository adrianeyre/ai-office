# A Spec is a Grilling Session

The Owner wants a Goal to become issues only after they have approved what it must do and how it will be built: today a chat request is filed and worked with no requirements or design the Owner approved first, and an issue's acceptance criteria are free text. So **a Spec is agreed in a Grilling Session**, started with the built-in `/spec <words>` Skill, that runs the session's rounds of questions in **three phases, in order: requirements, design, tasks**. The Manager's Model drafts the current phase's document as structured data (user stories with numbered Acceptance Criteria; the design's architecture, data, error handling and testing; ordered tasks naming the criteria they meet and the tasks they depend on), and **only the Owner's own words move it on**, read in plain code: "confirm requirements", "confirm design" (or "skip design", on any Floor) and "confirm tasks". Each confirmation keeps the draft as the **approved copy, stored with the session**, and commits it, as plain code writes it, in `.agents/specs/<slug>/` on the session's branch; "confirm tasks" opens the one pull request and keeps each task as one of the session's issue drafts. The Owner may reopen an earlier phase: its approved copy and every later one are dropped, and the later phases are drafted again.

## Considered Options

- **A free-form Spec document**, written in one go like `/to-spec`'s PRD and reviewed in its pull request: no new machinery, but nothing would stop the Model writing the tasks before the Owner agreed the requirements, and the criteria, tasks and dependencies would be prose that later steps could only guess at.
- **A pipeline of its own beside the Grilling Session**, with its own store, chat commands and whiteboard: the phases would fit it exactly, but it would duplicate the rounds, recommended answers, fact-finding, pausing, compaction and the documents' branch that the Grilling Session already has, and a Spec would behave unlike every other session.
- **The Manager decides when a phase is done**: fewer words for the Owner, but a model would then approve the requirements its own design is judged against, the step the Owner most wants to own.
- **A Grilling Session with phases the Owner confirms** (chosen): the session's rounds, history, fact-finding, pause and resume, End session and issue drafting all carry over, and the phases and approvals are a small, plain-code state kept with it.

## Consequences

- **The approved copy is the Spec.** It is kept in the database with the session, and every later prompt of the session quotes it word for word; Agents given the Spec later get that copy, never the file as it stands in the repository. A turn can change only the current phase's draft: an approved document cannot be rewritten without the Owner reopening its phase.
- **The session's branch holds exactly the approved documents.** A confirmation commits its document at once; a reopened phase's document, and the later ones, leave the branch until they are confirmed again; a design the Owner skipped is never written. The pull request is opened only when the tasks are confirmed (or the Owner ends the session with something confirmed), and is the Owner's to merge: the Merge Policy never merges a change under `.agents/specs/` ([ADR 0014](0014-agents-follow-only-guidelines-the-owner-approved.md)).
- **The tasks become the issue drafts in plain code**, one per task in the tasks' order, quoting the approved criteria each meets and blocked by the tasks it depends on, with no model asked. The Owner edits and files them as any session's drafts.
- **`/to-spec` is unchanged.** It still writes a PRD from the conversation so far; `/spec` writes a Spec. The two names are close, and the guide and the Skill list say which does what.
- A Spec takes more of the Owner's words than a Goal: three confirmations at least. That is the point, and a Goal still works as before for work that needs no Spec.
- Each Spec has its own folder, named from the words given to `/spec`, or with the session's number after it when the Floor already has a Spec of that name.
